# YANISKY Artwork Manager

## Спецификация v1

Дата фиксации: 2026-10-06  
Статус: архитектура данных зафиксирована перед реализацией.

## 1. Назначение

Artwork Manager является отдельным административным редактором произведений. Page Builder остаётся редактором страниц сайта.

Навигация Artwork Manager:

- Добавить картину
- Картины
- Серии
- Входящие
- Справочники

Редактор ориентирован прежде всего на ПК. Публичный сайт должен быть адаптивным.

## 2. Жизненный цикл произведения

Состояние записи и коммерческий статус существуют независимо.

Состояние записи:

- draft — Черновик
- published — Опубликована

Коммерческий статус:

- available — В наличии
- reserved — Зарезервировано
- sold — Продано
- in_progress — В процессе

Новая работа создаётся как Черновик.

Автосохранение изменяет рабочий черновик. Отдельная кнопка «Сохранить» также остаётся.

Предпросмотр открывает текущую сохранённую версию черновика в отдельной вкладке.

Публикация создаёт публичную версию. Последующие изменения снова сохраняются в черновик и не меняют публичную версию до следующего нажатия «Опубликовать».

«Скрыть с сайта» отзывает публичную версию и оставляет работу Черновиком.

Черновики находятся в общем разделе «Картины» с соответствующей маркировкой.

Удаляется только черновик. При окончательном удалении его изображения также удаляются из постоянного хранилища.

## 3. Artwork

У произведения есть стабильный внутренний ID, который не зависит от названия и URL.

Основные поля:

- id
- slug
- publicationState
- commercialStatus
- title
- description
- altText
- year
- category
- seriesId
- techniqueIds
- materialIds
- supportId
- tagIds
- dimensions
- originalPriceUsd
- createdAt
- updatedAt
- publishedAt

Текстовые поля хранятся по языкам. Пример:

    title: {
      ru: "...",
      en: "..."
    }

Размеры:

    dimensions: {
      width: 40,
      height: 50,
      depth: null,
      unit: "cm"
    }

Категория обязательна и принимает одно из трёх значений:

- traditional
- digital
- mixed_media

У картины одна основная серия и любое количество тегов.

Если авторская серия не выбрана, используется системная серия «Калейдоскоп случайного искусства».

## 4. Публичная и рабочая версия

Для опубликованной работы система должна различать:

1. workingDraft — текущие редактируемые данные;
2. publishedSnapshot — последняя версия, которую видит посетитель.

Автосохранение обновляет только workingDraft.

«Опубликовать» копирует актуальный workingDraft в publishedSnapshot.

Это позволяет менять уже опубликованную работу без мгновенного изменения публичного сайта.

## 5. ArtworkImage

Каждое изображение является отдельной записью.

Поля:

- id
- artworkId
- originalUrl
- displayUrl
- thumbnailUrl
- type
- sortOrder
- isMain
- width
- height
- mimeType
- fileSize
- createdAt

Тип:

- main
- detail
- interior
- other

Правила:

- одно главное изображение;
- дополнительных изображений может быть сколько угодно;
- порядок дополнительных меняется drag-and-drop;
- можно назначить другое главное;
- оригинальные пропорции не изменяются;
- оригинал хранится отдельно;
- для сайта создаются display и thumbnail версии;
- при окончательном удалении черновика связанные файлы удаляются из хранилища.

## 6. Series

Поля:

- id
- slug
- title
- shortDescription
- fullDescription
- periodStart
- periodEnd
- visibility
- sortOrder
- coverImageId
- createdAt
- updatedAt

title, shortDescription и fullDescription являются многоязычными.

Связь Artwork → Series: одна основная серия.

Системная серия «Калейдоскоп случайного искусства»:

- принимает работы без выбранной авторской серии;
- всегда отображается первой;
- её нельзя удалить;
- название можно переименовать.

Для общей страницы серий у серии хранится отдельный список featuredArtworkIds:

- максимум 5 работ;
- порядок задаётся вручную;
- работа отмечается как показываемая на общей странице серий.

Порядок остальных произведений внутри серии также задаётся вручную.

## 7. Dictionaries

Контролируемые справочники:

- techniques
- materials
- supports
- tags

Запись справочника:

- id
- key
- labels
- active
- sortOrder
- createdAt
- updatedAt

labels хранит переводы:

    labels: {
      ru: "Акрил",
      en: "Acrylic"
    }

Используемое значение нельзя удалить. Его можно переименовать.

При создании тега редактор предлагает перевод на активные языки. Перевод можно исправить вручную.

## 8. Языки

Глобально существует список активных языков.

Стартовая конфигурация:

- ru — основной
- en — дополнительный

Новый язык добавляется глобально, после чего соответствующее поле становится доступно у всех многоязычных сущностей.

Если публичного перевода текста нет, используется русский вариант.

Контролируемые значения переводятся через Dictionaries, а не вручную в каждой картине.

## 9. Дублирование

Дублирование создаёт новый Artwork:

- новый id;
- новый slug;
- publicationState = draft;
- изображения не копируются;
- дата публикации не копируется;
- текстовые и структурированные характеристики копируются.

## 10. Глобальные коммерческие функции

Коммерческие функции включаются глобально для всех произведений. Автору не требуется включать их на каждой картине.

Feature flags:

- originalSalesEnabled
- reproductionSalesEnabled
- licenseSalesEnabled
- customPriceRequestEnabled

Если функция выключена, её данные сохраняются, но публичный интерфейс её не показывает.

Точный сценарий оплаты, доставки, выдачи файлов и действия после продажи будет спроектирован отдельно.

## 11. Prices

Базовая авторская цена хранится в USD.

Для оригинала:

- originalPriceUsd

Репродукции и лицензии являются отдельными продуктами и имеют собственную модель цен.

Другие валюты рассчитываются автоматически по актуальному курсу.

Публичная валюта по умолчанию определяется языком сайта. Посетитель может изменить валюту вручную.

USD, введённый автором, не округляется системой. Конвертированные цены получают коммерческое округление.

## 12. Incoming

Private data. Никогда не публикуется в публичном JSON или публичном GitHub-репозитории.

Будущие типы:

- commission requests
- purchase inquiries
- custom price requests
- subscribers
- search analytics

Для поискового запроса хранятся как минимум:

- normalizedQuery
- displayQuery
- count
- lastSearchedAt

Одинаковые слова с разными грамматическими формами объединяются только когда их смысл совпадает. Совпадение корня само по себе недостаточно.

Запись поискового запроса можно удалить из административного списка.

## 13. GallerySourceConfig

Настройки порядка Gallery принадлежат конкретному источнику, а не самой картине.

Поля:

- id
- sourceType
- sourceId
- pinnedArtworkIds
- manualArtworkOrder
- quickFilterIds
- pageSize
- desktopColumns
- tabletColumns
- mobileColumns

sourceType:

- all
- category
- series
- tag

Для category sourceId принимает traditional, digital или mixed_media.

По умолчанию:

- pageSize = 18
- desktopColumns = 3
- tabletColumns = 3
- mobileColumns = 2

Максимум 6 pinnedArtworkIds на один источник.

## 14. Gallery Widget

Gallery Widget универсален. Источник выбирается в Page Builder и не показывается посетителю.

В Gallery допускаются только подходящие опубликованные работы.

Работы со статусом in_progress исключаются.

Masonry:

- одинаковая ширина колонок;
- исходные пропорции изображения;
- без обрезки и растягивания;
- следующая карточка добавляется в текущую самую короткую колонку.

Карточка:

- название;
- физический размер;
- цена;
- без года.

Если оригинал продан и репродукции включены, карточка показывает «Репродукция от …». Если репродукции выключены, показывает «Продано».

Клик открывает публичную страницу произведения.

Desktop hover:

- изображение слегка приближается;
- слегка меняет угол;
- название становится жирным;
- после ухода курсора состояние возвращается;
- соседние карточки не должны сдвигаться.

На touch-устройствах первое касание сразу открывает работу.

## 15. По вкусу автора

Сортировка по умолчанию: «По вкусу автора».

Для каждого Gallery source максимум 6 закреплённых работ.

В базовом режиме порядок:

1. закреплённые работы;
2. новые работы, опубликованные после последнего ручного сохранения порядка;
3. сохранённый ручной порядок остальных.

Новая работа не разрушает ручной порядок старых.

Если посетитель включает фильтр или другую сортировку, закрепление не влияет на позиции.

Автор меняет ручной порядок в редакторе Gallery Widget. Посетитель этого делать не может.

## 16. Gallery filters

Быстрые фильтры:

- «Все работы»;
- выбранные автором техники.

Редактор автоматически знает доступные техники, но автор сам выбирает, какие быстрые кнопки показывать и в каком порядке.

Расширенные фильтры:

- статус;
- основа;
- техника;
- серия;
- год;
- цена;
- размер;
- теги.

Совместимые фильтры комбинируются.

Активные фильтры показываются посетителю отдельными чипами с крестиком и «Сбросить всё».

При пустой выдаче:

- «По выбранным параметрам работ не найдено»;
- «Сбросить фильтры».

## 17. Gallery sorting

Варианты:

- По вкусу автора
- Сначала новые
- Сначала старые
- Цена по возрастанию
- Цена по убыванию
- Сперва маленькие
- Сперва большие

Размер сравнивается по самой длинной физической стороне произведения.

Статус, техника, основа и подобные параметры являются фильтрами, а не сортировками.

## 18. Gallery pagination

- 18 работ на страницу;
- пагинация по центру над masonry после фильтров;
- вторая пагинация под masonry;
- номера страниц кликабельны;
- стрелки назад и вперёд;
- после фильтрации число страниц пересчитывается;
- изменение фильтра возвращает на страницу 1;
- смена страницы прокручивает к началу Gallery;
- фильтры, сортировка и page записываются в URL;
- browser Back/Forward восстанавливает состояние.

## 19. Страница художественной категории

Traditional, Digital и Mixed Media используют одинаковую архитектуру из четырёх Page Builder widgets:

1. Навигация
2. Текст + картинка
3. Gallery
4. Карусель серий

Пагинация входит в Gallery Widget.

## 20. Публичный поиск

Глобальный поиск работает только в публичной версии сайта.

Поиск проверяет всю публичную информацию о произведении, а не только название.

Если результатов нет, предлагается ссылка на калькулятор заказа.

Запросы агрегируются во «Входящие → Поисковые запросы».

Для многословных запросов учитывается фраза и значимые слова. Служебные слова игнорируются.

## 21. Разделение публичных и приватных данных

Публичные:

- опубликованные версии произведений;
- публичные серии;
- публичные переводы;
- изображения для сайта;
- публичные цены;
- данные, необходимые Gallery и публичному поиску.

Приватные:

- рабочие черновики;
- внутренние заметки;
- подписчики;
- заявки;
- email;
- предложения цены;
- поисковая аналитика;
- административные настройки;
- история/служебные данные автосохранения.

Приватные данные никогда не должны попадать в site-data.json или другой публичный файл GitHub Pages.

## 22. Что намеренно отложено

До соответствующего этапа не фиксируются окончательно:

- точный публичный дизайн страницы картины;
- окончательная публичная страница конкретной серии;
- Series Carousel Widget;
- платёжная система;
- доставка;
- автоматическая выдача цифровых файлов;
- юридический текст коммерческой лицензии;
- точная модель печатных репродукций;
- действия системы после фактической продажи;
- окончательная SEO-схема.

## 23. Проверка противоречий

На текущем этапе критических противоречий в утверждённых решениях нет.

Уточнено:

- Черновик является состоянием записи, а не коммерческим статусом.
- «В процессе» является коммерческим статусом и не попадает в Gallery Widget.
- Видимость опубликованной версии управляется публикацией/отзывом публикации, отдельный третий публичный статус сейчас не нужен.
- Закрепление Gallery относится к источнику Gallery, а не глобально к Artwork.
- Публичная версия отделена от автоматически сохраняемого рабочего черновика.
- Справочники хранят переводы централизованно.
- приватные Inbox/analytics данные архитектурно отделяются от публичного сайта.

## 24. Следующий технический этап

Перед реализацией CRUD требуется выбрать постоянный технический фундамент:

1. база данных;
2. хранилище изображений;
3. безопасный административный доступ;
4. серверная/API часть, через которую Artwork Manager сохраняет приватные данные.

Это единственный оставшийся архитектурный блокер перед полноценным кодированием Artwork Manager.
